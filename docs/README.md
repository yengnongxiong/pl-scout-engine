# Project documents

Everything written about PL Scout Engine, and who each document is for.

| Document | What it answers | Best for |
|---|---|---|
| [`../PRD.md`](../PRD.md) | **What** we built and **why**: the problem, users, user stories, success metrics, milestones, and the outcomes against those targets (§21). | Product managers, recruiters, anyone new |
| [`METHODOLOGY.md`](METHODOLOGY.md) | **How** every number is calculated: per-90 rates, blending early-season data, possession adjustment, the fit score, the machine-learning models. | Analysts, engineers, curious fans |
| [`EVALUATION.md`](EVALUATION.md) | **How well** the models work, measured on live data (generated by `uv run scout train`). | Data scientists, engineers |
| [`decisions/`](decisions/) | **Why** big technical choices were made (Architecture Decision Records), e.g. [React instead of Streamlit](decisions/0001-react-typescript-frontend.md) and [ESPN instead of FotMob](decisions/0002-espn-possession-source.md). | Engineers, PMs |
| [`PROGRESS.md`](PROGRESS.md) | The **build log**: every task, decision and working session, written by the AI coding agent as it built the project milestone by milestone. | Anyone curious how an AI-built project is run |
| [`screenshots/`](screenshots/) | Images used in the main README, taken from the live dashboard. | — |

## Suggested reading order

- **Non-technical, 5 minutes:** the main [README](../README.md), then the PRD's summary and §21 Outcomes.
- **Product manager:** PRD (personas, user stories, success metrics, risks), then the ADRs and the build log.
- **Engineer or data scientist:** README "Under the hood", METHODOLOGY, EVALUATION, then the code guides in [`src/scout/`](../src/scout/README.md) and [`web/`](../web/README.md).
